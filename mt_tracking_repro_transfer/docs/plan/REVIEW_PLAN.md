## 审查目标

验证实现是否真正完成了“检测点属于哪条目标轨迹”的数据关联与轨迹管理，而不仅仅是画出平滑曲线。测试应使用已知 ground truth 的合成输入，并固定随机种子，保证每次结果可比较。

每个测试至少保存：

1. ground-truth target states：`frame, target_id, x, y[, vx, vy]`；
2. detections：`frame, detection_id, x, y[, confidence]`；
3. tracker output：`frame, track_id, x, y, matched_detection_id, status`；
4. 事件日志：birth、confirmation、miss、reacquisition、death、ID switch。

## 最小测试矩阵

### S0：输入/输出与空场景

- 0 个目标、0 个检测点，连续若干帧。
- 检查：不创建轨迹、不崩溃、不产生 NaN；输出 schema 稳定。
- 额外检查第一帧、最后一帧和空列表边界。

### S1：单目标、无噪声、无漏检

- 一个目标匀速直线运动，检测点与 ground truth 完全一致。
- 期望：恰好 1 条 confirmed track；每帧至多一个匹配；ID 全程不变。
- 位置误差应为 0（若输出的是滤波状态，需记录滤波延迟/初始误差的合理容差）。

### S2：单目标、有噪声

- 一个目标，加入固定 seed 的高斯测量噪声。
- 检查：误差有限且不发散；滤波后的误差不应系统性大于原始测量误差；不应产生重复轨迹。
- 若实现声明使用 gating，记录被拒绝测量数。

### S3：多目标、不交叉

- 2–5 个目标，初始位置和运动方向分离，轨迹间最小距离始终明显大于 gate 半径。
- 期望：轨迹数量与真实目标数一致；无 ID switch；每个目标的 ID 映射稳定。
- 检查错误合并、错误分裂和未匹配检测的比例。

### S4：双目标交叉

- 两个目标在中间时刻交叉或短暂接近，然后继续向不同方向运动；提供足够长的交叉前后窗口。
- 这是核心关联测试：交叉后应保持 target A→同一 track ID、target B→同一 track ID。
- 重点记录：ID switch 次数、交叉帧的关联概率/代价矩阵、轨迹是否交换、轨迹是否断裂。
- 不能只检查几何位置误差；即使位置误差小，ID 已交换仍应判失败。

### S5：短时漏检

- 单目标和双目标各做一次；在中间连续漏检 1、3、`max_age`、`max_age+1` 帧。
- 期望：短漏检期间 track 进入 missed/lost 状态但不立即删除；重新出现时恢复同一 ID。
- 若超过配置的生命周期阈值，允许删除，但必须记录明确 death 与后续新 birth，不得静默换 ID。

### S6：虚警

- 无真实目标时注入单个和多个虚警；再测试真实目标+虚警混合场景。
- 期望：孤立虚警不会立即形成 confirmed track；连续虚警的行为应符合明确的确认策略。
- 记录 false track 数、虚警被错误关联到真实 track 的次数，以及虚警导致的 ID switch。

### S7：出生/死亡

- 目标在中途出生；另一个目标在中途消失；测试同时 birth/death 和相邻帧事件。
- 期望：新目标经过明确 confirmation 规则后获得新 ID；死亡目标不会继续输出 stale state；存活目标 ID 不受影响。
- 检查轨迹 ID 是否复用。若复用，必须有 generation/生命周期区分，避免评估误判。

### S8：组合压力场景

- 至少 3 个目标，包含一次交叉、短时漏检、虚警、一次出生和一次死亡。
- 使用多个固定 seeds 重复运行。
- 该场景用于发现状态机之间的耦合问题，不用于定位单一模块错误；定位仍回到 S1–S7。

## 必须输出的指标

### 关联与身份指标

- detection-to-track association precision / recall / F1；只对有 ground-truth 归属的检测统计。
- ID switches：目标身份发生改变的次数。
- IDF1、ID precision、ID recall（如实现已有 MOT 评估器，优先采用标准定义）。
- Fragmentations：同一真实目标的轨迹被切断的次数。
- Mostly tracked / mostly lost（可选，但组合场景建议输出）。

### 轨迹与计数指标

- 每帧 active/confirmed track 数与真实目标数的差值。
- false tracks、false positives、missed detections。
- birth detection latency、death detection latency、reacquisition latency。
- track purity：一条输出 track 中占比最高的真实 target_id 比例。

### 定位与滤波指标

- matched position RMSE/MAE；分别报告 x、y 和二维欧氏距离。
- 速度 RMSE（若实现输出速度）。
- 每帧 cardinality error。
- OSPA、OSPA localization、OSPA cardinality（若论文复现范围包含这些指标）。
- 不要只报告总体均值：同时报告中位数、95th percentile，以及交叉/漏检窗口的局部结果。

### 稳定性与工程指标

- 每帧运行时间、总运行时间、峰值 active tracks、内存（可选）。
- 不同随机 seed 的均值和标准差。
- NaN/Inf、异常退出、空输入处理结果。

## 判定标准（建议初版）

- S0：零崩溃、零非法数值、零幽灵轨迹。
- S1：1 条轨迹，全程同一 ID，关联准确率 100%。
- S3：所有目标均被跟踪，无 ID switch、无错误合并/分裂。
- S4：交叉前后 ID 映射保持不变；任何一次身份交换都算失败，即使位置误差很小。
- S5：漏检不超过配置生命周期时保持原 ID；超过生命周期时产生可解释的删除/重生事件。
- S6：单帧或短串虚警不能直接造成 confirmed track，也不能污染真实目标轨迹。
- S7：birth/death 事件与日志一致，存活目标 ID 不被重置。
- S8：所有失败都应能归因到关联、gating、滤波或轨迹状态机中的具体模块。

阈值不能凭空宣称“复现论文结果”。应先从配置文件读取 `gate_threshold`、`min_hits`、`max_age`、确认阈值等，再把它们写入测试报告；若实现没有这些显式参数，应视为可审查性风险。

## 具体风险与改进建议

### R1：把位置连续性误当成身份正确

交叉场景中最近邻往往会交换 ID。必须把 ID switch 作为硬指标，并保存真实 target_id 到输出 track_id 的时间序列。

**建议：** 使用显式关联标签和交叉前后的 ID mapping；不要只看轨迹图。

### R2：轨迹生命周期参数隐藏或未定义

没有明确的 `min_hits/max_age`、确认、删除和重捕获规则时，漏检、虚警、出生/死亡无法客观判断。

**建议：** 将状态机和阈值配置化，并在事件日志中记录每次状态迁移。

### R3：gating 与代价矩阵单位不一致

位置单位、协方差、马氏距离和 gate 阈值若不一致，会导致关联大面积拒绝或错误吸附。

**建议：** 在诊断输出中同时记录欧氏距离、马氏距离、gate 判定和最终代价；写一个单位/尺度 sanity check。

### R4：虚警确认策略造成幽灵轨迹

若单帧检测即可创建正式轨迹，虚警会快速污染 ID 统计。

**建议：** 分离 candidate 与 confirmed 状态，测试 `min_hits=1/2/3` 的行为，并统计确认延迟。

### R5：漏检后的重捕获错误建新 ID

短漏检被删除或重捕获不使用历史状态，会产生 fragmentation 和 ID switch。

**建议：** 明确 lost 状态、预测窗口和重捕获 gate；对超过 `max_age` 的情况单独定义“合理重生”而非静默续接。

### R6：评估时错误使用未来信息

离线脚本若用完整轨迹或未来帧参与当前关联，会得到不可部署的虚高结果。

**建议：** 每帧只允许使用当前及过去信息；在代码审查中检查是否存在 future-frame lookahead。

### R7：随机数据与论文设置不一致

自行生成数据时，运动模型、噪声、漏检率、虚警分布和目标出生/死亡机制稍有不同，数值就不能直接和论文表格比较。

**建议：** 先报告配置差异，再比较趋势；若拿不到作者数据，不要把自生成数据的结果称为严格复现。

### R8：神经网络训练/评估泄漏

随机切分同一条轨迹的相邻窗口，或在测试时使用 ground-truth 轨迹数/身份，会高估 CTDA 性能。

**建议：** 按完整场景划分 train/validation/test；测试阶段只输入观测和 tracker 历史状态，不输入真实目标 ID 或真实数量。

### R9：只验证平均指标，掩盖交叉失败

大量简单帧会稀释少量关键交叉帧的 ID switch。

**建议：** 同时报告总体指标与事件窗口指标，至少单独报告交叉前后、漏检窗口和 birth/death 窗口。
